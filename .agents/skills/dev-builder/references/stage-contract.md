# 开发阶段契约

## 输入

有效预期行为、范围/非目标、验收和授权；产品需求与短任务/Phase，或维护契约。不要求每个任务同时有 Spec 和 DEV-PLAN。

## 交付条件

- 行为与当前有效契约一致，相关验证能解释证明了什么、未证明什么。
- 新增外部行为按产品变更记录，不能塞入维护队列掩盖。
- 已更新受影响现状、有效需求、设计与计划；旧决定被替代且引用可追溯。
- R2 的独立审查有真实结果；用户限制或宿主限制导致的缺口如实保留。
- 复用基于当前相关文件和环境的证据；他人并行修改未验证时不宣称覆盖。

## 轻量任务

R0/R1 直接执行，不派遣子代理。轻量维护在 `docs/maintenance/batch.md` 留 ID、范围、结果、证据链接和待复查状态；已有同任务记录就更新。产品小改用需求/短任务留痕。

待复查不替代即时必要验证。用户明确要求或授权发布/合并准备时批量复核；主会话在同次收尾保留回执、移出已关闭项，全部关闭则重置队列。未解决、未覆盖及审查后新增/实质修改的项保留，按共同契约执行。不因队列存在重复询问相同授权。

## 审查、文档和状态

使用[共同契约](../../../../.creator/references/workflow-contract.md)的证据适用性、进展检查和恢复规则；不在此复制另一套风险表。实施完成、审查待补、未发布分别表述，旧审查轮数不阻止实质修复后的新证据闭合。

## Examples

更新已确认的本地显示选项：短产品任务、针对性验证、同步需求与说明；无具体重大风险不启动 R2 审查。

真实权限边界修改：即使只有一行，也证明隔离与拒绝路径并安排相应独立审查。
