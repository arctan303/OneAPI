# Phase-01：本地账号、日志与key控制

状态：本地实施完成；Mock/SDK/浏览器及真实账号验收通过；fresh R2 独立复核通过，无剩余可执行问题；未云端部署，本轮扩展未推送。依据DEC-011与EXPLORE-001；基线v0.1.0。depends_on：LIVE-001已验证的原账号、Node传输、两种协议与APIkey管理。

目标：在原本地后台验收REQ-09/10/11/12以及REQ-03/04/08兼容性。非目标：云端部署、其他厂商协议、多人角色、重置账号、后台自动试遍全部模型。

任务：先用现有网关OAuth对官方usage端点做有界只读验证；实现账号卡片。统一key鉴权返回稳定key身份，落地白名单/有效期/停用/限速并发和按key目录。用户追加思考程度：完善两协议每次请求参数、官方模型目录能力元数据、动态后台选择框与目录缓存生命周期；适配器不限制在旧枚举，仍以账号目录确认。随后实现默认精简、可选正文的有界日志与后台筛选详情，完善两种协议的字段兼容矩阵。常规日志与正文采集均保留流取消/背压语义，usage缺失标未知。

迁移：扩展现有数据，不改现有密钥和OAuth值；旧key保持调用行为。新增字段默认值与保留策略见EXPLORE-001。日志与测试数据留在忽略存储内，不提交Git。回滚前核对新增存储字段兼容性，不删除原数据库。

风险R2：模型授权改动可能绕过key限制；记录正文涉及敏感信息；新增官方出站目标携带OAuth。针对验证：各入口同权与目录过滤、到期/停用/限流拒绝不消耗上游、跨key隔离、两请求并发取消和名额回收、正文开关/过期/超限/错误、未知usage、秘密不落日志、固定出站与拒重定向。使用一个fresh reviewer并按实质修复聚焦复核。

验收：Mock/SDK/浏览器覆盖相关行为，保持旧回归；真实检查只读取自己的官方额度，用gpt-5.5完成有界新key普通与页面流式测试，确证日志模型/状态/官方usage和权限行为。不得通过重复真实请求代替本地回归。额度字段不提供或端点被拒仅阻碍对应额度能力，记录原因后继续其他工作。登录失效需要用户操作时通知，不反复重登。

证据入口：[PHASE-01](../verification/PHASE-01.md)。官方七天窗口真实可读，未解析到通用5h时显示未知；已部署本地新版后端，保留原OAuth。输出：更新有效产品契约/现状、实现与测试、真实证据和R2回执。Phase-02 保留为后续隔离云端验证，本轮停在已验收的本地交付。
