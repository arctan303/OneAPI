## 执行顺序与默认值

先完成本地扩展并端到端验收，再进行隔离 Cloudflare 测试。额度先做有限只读联通验证；其失败只影响额度卡片，不阻止日志和key控制继续开发。协议范围是 OpenAI Chat Completions 与 Responses，不扩展其他厂商格式。

用户明确：额度就是官方返回的当前账号七天/5h窗口用量与各自重置时间。每条调用的token只用上游响应usage，缺失显示未知而非0；不存在按本网关日志估算官方订阅额度的需求。

以下为实施默认值，不冒充用户逐项指定：精简日志保留30天、完整正文7天，后台可调整；正文默认关闭，仅影响开启后的请求，关闭即停止新正文采集，已有记录按保留策略处理。开启状态在请求开始时确定，避免中途切换产生半份记录。输出超限/取消/缺少usage必须有明确标记；日志故障不把已成功生成伪报成失败。

已有key迁移保留原调用能力、不变更密钥值；新增key可选择全部模型或指定白名单，选择白名单时不自动放行后来出现的新模型。目录与两种生成协议统一校验，包含兼容的旧环境调用密钥。key默认不过期、限速默认不额外限制并受原全局并发上限约束；管理员可以指定到期、停用、恢复、限速与并发。权限/状态修改约束新请求，已开始的请求按既有生命周期处理；停用不删除历史日志。

已接受的附加功能为key有效期/临时停用、按key限速/并发限制；轮换可以沿用创建新key再撤销旧key的现有流程。网站CORS和Cloudflare Access在后续测试部署中验收，API机器调用不能被交互式登录页破坏。

## 可行性与待验证边界

官方 App Server 已有 account/read（邮箱/套餐）及 account/rateLimits/read（usedPercent、windowDurationMins、resetsAt、multi buckets）。这证明存在客户端数据能力，不等于OneAPI当前绑定已能直连。官方固定提交 4aec23384e85734bbae3a3eed06a9218babc4e51 的 backend-client 使用 GET /backend-api/wham/usage；可复用本网关自己的 Bearer/Account-ID。Phase-01 已加入该固定路径并真实读取官方七天额度；无通用 5h 规范化窗口时显示未知，额外模型窗口单列。真实证据和出站 R2 复核见 PHASE-01。

有七天/5小时就展示实际窗口；剩余百分比是100-usedPercent，不能推算成准确剩余token或可调用次数。额度只读失败时显示未获取、原因与最后成功时间，不用网关调用日志补造。

目前未确认上述核心需求存在不可实现的阻碍。明确边界：网关看不到其他客户端的完整请求记录；上游没有提供的隐藏/加密内容不能还原；中断或未记录的历史正文不能补回；不支持的上游功能不能靠协议转换创造。若真实额度端点持续拒绝或缺失所需字段，才按证据记录对应能力阻碍。

参考：[官方 App Server](https://learn.chatgpt.com/docs/app-server)、[官方额度请求实现](https://github.com/openai/codex/blob/4aec23384e85734bbae3a3eed06a9218babc4e51/codex-rs/backend-client/src/client/rate_limit_resets.rs)、[官方账号字段解析](https://github.com/openai/codex/blob/4aec23384e85734bbae3a3eed06a9218babc4e51/codex-rs/login/src/token_data.rs)。这些是需求确认时的研究边界；后续实施与真实验收见 [PHASE-01](../verification/PHASE-01.md)。
