## 对纯 Worker 目标的影响

结合 [MARKER-001](MARKER-001.md)：同 Node 进程同凭据，原请求200，只增加CF-Worker后403；本次换到官方WebSocket传输仍403。来源标记是本项目已复现的拒绝触发因素，具体执行规则仍未获上游确认。不能将全部原因简化为机房IP，也不能从HTML403识别具体WAF规则ID。

[Cloudflare官方说明](https://developers.cloudflare.com/fundamentals/reference/http-headers/#cf-worker)表示所有Worker fetch子请求都会附加CF-Worker，WAF匹配则使用cf.worker.upstream_zone。这解释了业务JavaScript删头无法保证消除平台来源信息；本次没有已验证的纯Worker修复。

当前阻碍：上游拒绝当前Worker来源，已验证的HTTP与官方WebSocket传输均不通。恢复需要上游允许该来源、提供可用的受支持入口，或出现新的具体可复现实例；仅增加重复请求不能补齐这些条件。现有 [支持草稿](PURE-WORKER-support-draft.md) 可以复用真实对照，尚未对外发送。如果另选有独立出站能力的云端运行服务，需记录为架构变更，不能宣称仍是单Worker，也不等于必须使用本地电脑。
