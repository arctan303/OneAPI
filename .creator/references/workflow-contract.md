# 共同工作契约

本文件是阶段技能共用的细则，按任务阅读相关章节；路线、分级和授权以项目系统指令为准，不从历史版本重载旧规则。

## 当前知识与决策

- 现状入口回答能力、架构/模块、运行与验证入口、当前里程碑、限制和资料导航。现有 README/MANUAL/PROJECT-CONTEXT 能承担时复用，不要求统一改名。
- 需求表达当前有效预期，现状表达实际核验结果；计划表达下一步，历史只解释当时选择与证据。待实现不写成已实现，本地通过不写成已上线。
- 重大决定保留稳定 ID、适用范围、状态（待定/有效/已替代/已撤销）和依据；被替代时注明新决定 ID 或明确来源链接。普通小改不制造 ADR 文件。
- 新决定确认后同次更新受影响需求、设计、活跃任务；旧条款在当前正文被修订/移出，历史只补替代元数据，不篡改当时任务或证据。
- “暂不做”注明适用基线或重审条件；后续承接时撤销旧限制。证据冲突先分类，不能只按时间较新或代码现状决定正确行为。

## 计划与承接

- Phase 适用于用户点名或多个有依赖、分别验收的阶段；其余使用短任务。路由到计划技能也可以输出短任务，不为凑 Phase 拆碎工作。
- 已有相关活跃任务优先更新。Phase ID 稳定，文件搬迁不重编号；未开始阶段可调整，不受“历史只读”保护。
- 计划索引只保留当前/必要后续阶段和历史导航；不要在索引复制每条验收与命令。
- 阶段至少包含以下信息（可以使用项目等价格式）：

```markdown
# Phase <稳定 ID>：<能力>
目标与范围/非目标：
依据：需求/变更 ID 或用户确认来源
depends_on：前置 ID + 本阶段实际需要的成果；没有则明确无
supersedes：有替代关系时列旧 ID 与原因
任务与预期产物：
验收与验证：
风险及具体影响：
状态与证据：
```

- 前置阶段标完成不保证所需成果今天仍有效，开工核对相关接口/文件。后继关系从 depends_on 派生，不维护两套关系表。
- 缺失历史只记未知和可证实的当前基线；不能编造 Phase、REQ/AC、审查或测试结果。后续以新的有效任务承接。

## 状态、证据与审查

复杂任务按需拆开：实施（未开始/进行中/完成）、验证（待验证/通过/失败/缺口）、审查（不适用/待审/通过/问题待处理/例外）、发布（未发布/已发布/未核验）。整体可以“本地完成，审查待补”，不一律标已阻塞。

证据说明命令、结果、对应验收和适用代码/环境；运行证据与结构检查分别说明。相关内容改变后只失效受影响证据；不能沿用基于旧文件的审查结论证明新文件，也不能把他人并行修改纳入自己的已验证范围。

reviewer 收到有效契约、风险理由、相关变更基线、验证证据、已知问题和授权边界；不得只收到实现者自评。首审汇总可执行发现，聚焦复核原问题与相邻回归；严重的新问题也需报告，但不自动扩展成全仓审计。

每次复核记录关闭/剩余问题和新增证据。默认在首审后的第 2 次聚焦复核结束时做一次进展检查：有具体剩余风险、可执行修复且继续推进仍在授权/资源范围内，则继续；连续两轮无实质进展或达到用户预算则暂停并写恢复入口。这是进展检查，不是“两轮后永久禁止审查”。

用户接受的例外必须保留具体门禁、风险、授权来源和适用变更，不转成审查通过或普遍豁免。只阻止真正依赖未解决条件的任务。

## 轻量维护队列

- `docs/maintenance/batch.md` 只承载当前待复查批次，不作累计日志。R0/R1 的已验证维护由当前会话执行并入队；每项留稳定 ID、范围、简短结果、证据链接和待复查/问题待处理状态。已有项原位更新，不重复追加。
- 新产品能力、R2 或未完成必要验证的任务不能靠入队代替需求/即时验证；小型产品变更用需求/短任务留痕。
- 不自动逐项审查。用户要求批量审查或已授权发布/合并准备时，记录本次覆盖的条目 ID、相关 diff 和证据基线，按全局审查规则执行。
- 收到审查结果后，主会话在本次收尾中移出已通过且证据仍适用的条目；未解决、未覆盖、审查中断或有条件通过但条件未落实的项继续留队。有效授权例外可以按其范围关闭，但记录为例外，不写成通过。reviewer 负责给结论，主会话负责更新队列。
- 移出前复用已有审查/发布记录保留批次 ID、覆盖条目、结论和证据链接；无适用记录时只建一份 `docs/maintenance/reviews/<batch-id>.md` 批次回执。唯一的任务或验证明细先完整迁存，不为每条小改建档、不重复复制已有证据。
- 部分通过只清理对应项；清理前重读队列，审查开始后新增或实质修改的项不算已审，保留给后续复核。不能整文件覆盖或顺手删除其他任务的条目。
- 全部关闭后重置原文件，只留标题、“当前无待复查项”和最近一次回执链接；不保留已复查表、旧批次清单或累计统计。下一批复用文件路径但使用新的批次/条目 ID，不复用旧 ID。再次清理空队列不新建回执、不刷新记录。

## 维护责任与增长控制

| 环节 | 同次更新 |
| --- | --- |
| 需求确认 | 当前条款、决定替代关系、待实现标记 |
| 设计变化 | 当前设计规则及受影响引用，不把审美材料扩大为功能需求 |
| 规划 | 相关范围对账、依赖、活跃任务，不重抄历史 |
| 开发/修复 | 验证后更新受影响能力、模块/命令/限制及任务状态 |
| 审查 | 检查上述相关文档是否同步、旧决定是否失效、证据是否仍适用 |
| 发布 | 对应版本/环境和真实回读证据；不凭构建推断生产状态 |

没有影响现状摘要的小改无需改入口。不要每轮写流水账；阶段完成、决定替代、归档和实质变化时整理。

现状入口建议约 150 行或 8 KiB 内便于扫读，详细主题约 300 行或 20 KiB 时检查拆分必要性；任一超过只是整理提示，不自动失败。也检查重复内容、长表格和 token 负担。不能压成超长行规避，更不能删除证据凑预算。

内容变大时按模块/职责下沉，入口留短摘要与链接；复杂 Phase 将多轮证据分到关联文件；历史按里程碑归档，历史索引也可分层。保留完整任务与验证，不让所有历史重新进入默认上下文。
